\chapter{LANGUAGE DESIGN AND GRAMMAR}

\section{Types}
The language supports four primitive types. These types are sufficient to cover
the assignment requirements while keeping the semantics simple and predictable.

\subsection{Integer}
The Integer type represents whole numbers such as \texttt{0}, \texttt{7}, and
\texttt{42}. Integer literals are written as one or more decimal digits without
quotation marks or a decimal point.

\subsection{Float}
The Float type represents real-valued numbers written with a decimal point, such
as \texttt{3.14} or \texttt{20.5}. Float values are used in arithmetic
expressions and also arise as the result of any division. Division always
produces a \texttt{Float} even when both operands are \texttt{Integer}: for
example, \texttt{10 / 2} evaluates to \texttt{5.0 : Float}. This is an
explicit design rule enforced in the type checker.

\subsection{Boolean}
The Boolean type represents logical truth values. The two Boolean literals are
\texttt{true} and \texttt{false}. Boolean values are used in conditions and as
results of comparison expressions.

\subsection{String}
The String type represents sequences of characters enclosed in double quotes,
for example \texttt{"hello"}. Strings can be assigned to variables and printed
through the built-in \texttt{print()} function. The surrounding quotes are
stripped by the parser when the \texttt{Literal} node is created, so the value
stored internally is the bare character sequence without surrounding quotes. At
runtime, the built-in \texttt{print()} function re-adds double quotes around
string values, so \texttt{print("plc")} outputs \texttt{"plc" : String}.

\subsection{Void}
\texttt{Void} is an internal type used by the type system to represent the
return type of functions that contain no \texttt{return} statement. It is not
a type that programmers write explicitly; it exists solely inside the
\texttt{LanguageType} enum so that the symbol table can record a well-defined
type for every function definition, including those that produce no value.

\section{Static Typing}
The language uses static typing, which means type errors are detected before
execution rather than during program execution. No explicit variable type
declarations are required. Instead, the type checker infers types from literals,
assignments, operations, function calls, and return statements. Once a variable
type is established, later assignments must remain consistent with that type.

\section{Context-Free Grammar}
The language grammar can be described by the context-free grammar
$G = (V_N, V_T, P, S)$, where $V_N$ is the set of non-terminals, $V_T$ is the
set of terminals, $P$ is the set of production rules, and $S$ is the start
symbol \texttt{program}. The grammar is implemented through recursive-descent
parsing functions.

\subsection{Program Structure}
\begin{lstlisting}
program   -> statement* EOF
statement -> assignment ';'
	   | if_stmt
	   | while_stmt
	   | func_def
	   | print_stmt ';'
	   | return_stmt ';'
	   | expr ';'
\end{lstlisting}

\subsection{Arithmetic Expressions}
\begin{lstlisting}
expr   -> term (('+' | '-') term)*
term   -> factor (('*' | '/') factor)*
factor -> '-' factor
	| INT_LITERAL
	| FLOAT_LITERAL
	| STRING_LITERAL
	| BOOL_LITERAL
	| IDENTIFIER
	| IDENTIFIER '(' args? ')'
	| '(' expr ')'
\end{lstlisting}

The unary minus production allows negative literals such as \texttt{-5} and
negated variable references such as \texttt{-x}. It is implemented as a
right-recursive descent into \texttt{factor} and is desugared internally to
\texttt{0 - factor}, so all existing type rules for arithmetic apply without
modification.

\subsection{Boolean Expressions}
\begin{lstlisting}
bool_expr -> expr '==' expr
	   | expr '!=' expr
	   | BOOL_LITERAL
\end{lstlisting}

Boolean expressions are only parsed as conditions inside \texttt{if} and
\texttt{while} statements. Comparison results are not storable in variables
directly; the grammar does not include \texttt{bool\_expr} in the
\texttt{factor} rule. This is consistent with the assignment specification,
which describes Boolean expressions primarily as conditions.

If \texttt{bool\_expr} parses an expression and finds no following \texttt{==}
or \texttt{!=} operator, the expression is returned as-is and the type checker
verifies that its inferred type is \texttt{Boolean}.

\subsection{Statements}
\begin{lstlisting}
assignment  -> IDENTIFIER '=' expr
if_stmt     -> 'if' '(' bool_expr ')' block ('else' block)?
while_stmt  -> 'while' '(' bool_expr ')' block
print_stmt  -> 'print' '(' expr ')'
return_stmt -> 'return' expr
block       -> '{' statement* '}'
\end{lstlisting}

\subsection{Function Definitions and Calls}
\begin{lstlisting}
func_def -> 'def' IDENTIFIER '(' params? ')' block
params   -> IDENTIFIER (',' IDENTIFIER)*
args     -> expr (',' expr)*
\end{lstlisting}

Function calls use value parameter passing. This means the argument values are
evaluated before the call and copied into the function's local environment.

\section{Operator Precedence and Associativity}
Operator precedence is encoded structurally in the recursive-descent parser.
Comparison is lowest, addition and subtraction are next, and multiplication and
division have the highest precedence among binary operators. Arithmetic
operators are left-associative.

\begin{table}[H]
\centering
\caption{Operator Precedence (1 = lowest, 3 = highest) and Associativity}
\begin{tabular}{lll}
\toprule
Precedence & Operators & Associativity \\
\midrule
1 (lowest) & \texttt{==}, \texttt{!=} & non-associative (condition use only) \\
2 & \texttt{+}, \texttt{-} & left-associative \\
3 (highest) & \texttt{*}, \texttt{/} & left-associative \\
\bottomrule
\end{tabular}
\end{table}
