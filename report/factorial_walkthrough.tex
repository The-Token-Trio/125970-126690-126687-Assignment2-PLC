\section{Source Program}

Recursion is not supported by the type checker; factorial is computed
using an accumulator variable inside a \texttt{while} loop.

\begin{lstlisting}[caption={Iterative factorial program},label={lst:source}]
def factorial(n) {
    result = 1;
    i = n;
    while (i != 0) {
        result = result * i;
        i = i - 1;
    }
    return result;
}

x = 5;
f = factorial(x);
print(f);
\end{lstlisting}

\noindent\textbf{Lexer notes.}
Keywords (\texttt{def}, \texttt{while}, \texttt{return}) are emitted as
dedicated token types; all other names including \texttt{factorial} and
\texttt{print} are emitted as \texttt{IDENTIFIER}.  The two-character token
\texttt{!=} is recognised by consuming \texttt{!} and peeking ahead for
\texttt{=}.  No float literals or dot-suffixed operators appear in this program.

\subsection*{Mini \texttt{if-else} walkthrough: input $\rightarrow$ lexeme $\rightarrow$ token $\rightarrow$ parse tree}
The factorial program itself does not contain an \texttt{if} statement, but
the professor specifically asked for a clean \texttt{if-else} example showing
the full system process on separate lines. The example below presents that
chain explicitly.

\noindent\textbf{Input source string}
\begin{lstlisting}[language={},numbers=none,frame=single,backgroundcolor=\color{codebg}]
if (x == 0) { print(x); } else { print(y); }
\end{lstlisting}

\noindent\textbf{Lexeme sequence}
\begin{lstlisting}[language={},numbers=none,frame=single,backgroundcolor=\color{codebg}]
if   (   x   ==   0   )   {   print   (   x   )   ;   }   else
{   print   (   y   )   ;   }
\end{lstlisting}

\noindent\textbf{Token sequence delivered to the parser}
\begin{lstlisting}[language={},numbers=none,frame=single,backgroundcolor=\color{codebg}]
IF LPAREN IDENTIFIER EQUAL_EQUAL INT_LITERAL RPAREN
LBRACE IDENTIFIER LPAREN IDENTIFIER RPAREN SEMICOLON RBRACE
ELSE
LBRACE IDENTIFIER LPAREN IDENTIFIER RPAREN SEMICOLON RBRACE
\end{lstlisting}

\noindent\textbf{Lexeme-to-token definition}
\begin{lstlisting}[language={},numbers=none,frame=single,backgroundcolor=\color{codebg}]
'if'    -> IF
'else'  -> ELSE
'('     -> LPAREN
')'     -> RPAREN
'{'     -> LBRACE
'}'     -> RBRACE
'=='    -> EQUAL_EQUAL
'0'     -> INT_LITERAL
'x','y','print' -> IDENTIFIER
\end{lstlisting}

\noindent\textbf{CFG rules containing those tokens}
\begin{lstlisting}[language={},numbers=none,frame=single,backgroundcolor=\color{codebg}]
if_stmt    -> IF LPAREN expr RPAREN block else_part
else_part  -> ELSE block | epsilon
block      -> LBRACE stmt_list RBRACE
expr       -> comparison | additive
comparison -> additive EQUAL_EQUAL additive
\end{lstlisting}

\noindent This mini example makes the separation explicit:
the \emph{input string} contains raw characters,

and the \emph{parse tree} is the hierarchical concrete-syntax view produced
after parsing that token sequence.

\section{Stage 2 --- Parsing}

The recursive-descent parser consumes the token string and builds an
Abstract Syntax Tree (AST).  Assignments are distinguished from expression
statements by one-token lookahead (\texttt{IDENTIFIER} followed by
\texttt{ASSIGN}).  Operator precedence is encoded structurally across three
rule levels:

\begin{center}
\begin{tabular}{ll}
  \toprule
  \textbf{Rule} & \textbf{Handles} \\
  \midrule
  \texttt{\_expr()}     & Comparison (\texttt{EQUAL\_EQUAL}, \texttt{BANG\_EQUAL}) \\
  \texttt{\_additive()} & Addition / subtraction (\texttt{PLUS}, \texttt{MINUS}, \texttt{PLUS\_DOT}, \texttt{MINUS\_DOT}) \\
  \texttt{\_term()}     & Multiplication / division (\texttt{STAR}, \texttt{SLASH}, \texttt{STAR\_DOT}, \texttt{SLASH\_DOT}) \\
  \texttt{\_factor()}   & Literals, identifiers, calls, grouped expressions \\
  \bottomrule
\end{tabular}
\end{center}

\subsection*{Grammar Rules Applied}

The productions below fire for each construct in the factorial program.
\textbf{Uppercase names are terminal token types} (from the Token Grammar);
lowercase names are non-terminal symbols.

\begin{lstlisting}[language={},numbers=none,frame=none,backgroundcolor=\color{white}]
(* Function definition *)
func_def    -> DEF IDENTIFIER LPAREN params RPAREN block
params      -> IDENTIFIER
block       -> LBRACE stmt_list RBRACE

(* Statements inside the function body *)
assignment  -> IDENTIFIER ASSIGN expr SEMICOLON
while_stmt  -> WHILE LPAREN expr RPAREN block
return_stmt -> RETURN expr SEMICOLON

(* Expressions used in the factorial program *)
expr        -> comparison | additive
comparison  -> additive BANG_EQUAL additive       (* i != 0 *)
additive    -> term MINUS term                    (* i - 1  *)
term        -> factor STAR factor                 (* result * i *)
factor      -> INT_LITERAL                        (* 1, 5, 0 *)
             | IDENTIFIER                         (* i, n, result *)
             | IDENTIFIER LPAREN args RPAREN      (* factorial(x), print(f) *)

(* Top-level statements *)
assignment  -> IDENTIFIER ASSIGN expr SEMICOLON   (* x = 5; f = factorial(x); *)
\end{lstlisting}

\noindent\textbf{Note on \texttt{if}/\texttt{else}.}
Although this program contains no \texttt{if} statement, the grammar rule
uses token names --- not quoted strings --- for every terminal:
\begin{lstlisting}[language={},numbers=none,frame=none,backgroundcolor=\color{white}]
if_stmt   -> IF LPAREN expr RPAREN block else_part
else_part -> ELSE block | epsilon
\end{lstlisting}

\section{Stage 3 --- Type Checking}

The type checker performs a single-pass, syntax-directed AST traversal.
Types are inferred from literals, operators, and call sites --- no
annotations are required.  The first call \texttt{factorial(x)} fixes the
parameter type \texttt{n : Integer}, after which the function body is
checked in a dedicated scope.

\subsection*{Function Body Type Inference}

\begin{center}
\begin{tabular}{p{5cm}p{2.5cm}p{5cm}}
  \toprule
  \textbf{Statement} & \textbf{Inferred type} & \textbf{Action} \\
  \midrule
  \texttt{result = 1}
    & \texttt{Integer}
    & Record \texttt{result : Integer} in function scope. \\[4pt]
  \texttt{i = n}
    & \texttt{Integer}

\noindent\textbf{Recursion note.}
The type checker tracks active calls in \texttt{\_active\_calls}.  A
recursive call such as \texttt{return n * factorial(n - 1)} would be
rejected with \texttt{TypeCheckError: Recursive function calls are not
supported: factorial}.  The iterative formulation avoids this entirely.

\section{Stage 4 --- Interpretation}

The tree-walking interpreter executes the validated AST using a chain of
\texttt{\_Environment} objects for scoped variable storage.  Each function
call creates a new environment linked to the caller's.

After binding the parameter and initialising locals, the function environment is:
\[
  \textit{call\_env} = \{\;\texttt{n} \mapsto 5,\;\texttt{result} \mapsto 1,
                            \;\texttt{i} \mapsto 5\;\}
\]

Table~\ref{tab:execution} traces the \texttt{while} loop iterations.

\begin{table}[H]
  \centering

\noindent After the loop:
\[
  \textit{call\_env} = \{\;\texttt{n} \mapsto 5,\;\texttt{result} \mapsto 120,
                            \;\texttt{i} \mapsto 0\;\}
\]

\noindent \texttt{return result} raises \texttt{\_ReturnSignal(120)}, caught
by \texttt{\_call\_function()}, which returns \texttt{120}.
The global environment becomes
$\{\texttt{x} \mapsto 5,\;\texttt{f} \mapsto 120\}$, and
\texttt{print(f)} outputs:
\[
  \texttt{120 : Integer}
\]
